# Pay Skill 接入草案

目标是在 SkillHub 上架 Pay Skill。已确认没有现成收费 API，需要新建提示词生成服务。本文是待实现的方案，当前仓库没有可收款的后端。

## 服务边界

客户端 skill 负责澄清研究用途、保留用户约束和整理上下文；收费后端使用模型生成完整 Deep Research 提示词。一次收费对应一次明确的生成请求和交付结果，不包含真正执行 Deep Research。付款前说明会发送哪些研究内容、交付内容和价格。

保留原有“按需追问、信息充分时直接生成、已有提示词完整改写”的体验。付费接口不向用户增加固定规格问卷。模型指令沿用现有设计，新的客户端和服务端行为需要重新评测，不能沿用旧版本结果宣称付费流程已通过。

## 实现与验证

1. 确定单次价格、模型服务和部署位置，接入真实模型调用及持久化订单存储。生产凭据只使用部署环境的秘密配置。
2. 为研究输入生成订单，固定输入摘要、金额和服务版本；服务端决定金额。以订单号和支付交易号的唯一约束防止跨请求复用凭证或重复收费交付。
3. 按支付宝实际可用协议返回 HTTP 402，通过官方买家支付能力完成付款。服务端向支付宝验证凭证、金额和订单关联后才开始生成。
4. 持久化生成结果后确认履约。重复请求返回同一结果；生成失败、确认失败和进程重启均可恢复，避免要求已付款用户重新购买。模型调用超时与进程中断需单独验证，不能声称能保证上游模型恰好调用一次。
5. 覆盖无凭证、伪造凭证、金额不符、订单输入变化、并发重试、模型失败、履约确认失败和重启恢复；然后完成支付宝沙箱联调与新行为评测。
6. 完成商家入驻、产品开通、真实服务登记及 HTTPS 部署，核对 SkillHub、支付宝与服务端价格一致，再打包提交审核。

具体语言、存储和部署配置在部署位置确定后选择，不把模拟支付作为生产实现。

## 协议核对记录（2026-11-03）

当前官方材料存在版本差异：

- [SkillHub 指南](https://skillhub.cn/tutorials#alipay-pay) 与支付宝官方 npm 包 `@alipay/alipay-aipay@1.8.0` 的 `aipay-interface-contract.md` 使用 `Payment-Needed` 账单、`Payment-Proof`、验付和履约确认。
- [支付宝在线接入指南](https://aipay.alipay.com/docs/ai-receive/MACHINE_PAY.html) 使用 `alipay.aipay.agent.payment.precreate` 创建预下单，并返回 `amtPaymentLink`。
- [最新验付接口](https://aipay.alipay.com/docs/ai-receive/api-list/alipay-aipay-agent-payment-verify.html) 标注 `resource_id` 已废弃，而 npm 包示例仍要求校验该字段。

接入前需通过官方沙箱与 SkillHub 买家调用链确认适用协议。不能把两套协议字段随意拼接，也不能因字段缺失跳过金额与订单绑定检查。当前仅下载阅读官方包，未执行其安装、遥测或账户操作。
