# 行为评审标准

只向评审提供本文件、案例要求和匿名输出。生成提示词的代理不能看到本文件或案例中的 expected、must_not。

对每份输出给出以下五项结论。每项只取 pass 或 fail，附输出中的具体依据。不要因措辞、标题或排版差异扣分。

| ID | 标准 |
| --- | --- |
| intent | 回应用户实际用途，保留明确范围和约束。修订任务清除旧条件，冲突任务不静默择一。 |
| interaction | 信息不足时问有价值的问题。信息充分或要求直接出稿时交付。尊重不再提问和仅改写的要求。 |
| autonomy | 方法与表达匹配任务，不强加规格问卷、市场框架、来源配额、权重或操作步骤。保留用户主动要求的细节。 |
| usable | 需要交付时，提示词能够脱离聊天执行且没有待填变量。合理的澄清轮只需提出足以推进的问题。冲突任务允许清楚标注的互斥分支。 |
| evidence | 生成的研究任务要求可追溯证据，区别推断与事实，处理相关反证和局限。澄清轮不强制展开证据协议。任何输出都不能编造事实、引用或已经完成的研究。 |

任一项 fail，该份输出不通过。只有所有预定输出均存在、五项均通过、工具记录确认读取了入口文件，才允许本次发布。缺失输出、运行错误和无法确认读取均为不完整，不能算通过。

这是一组回归案例，每个案例在每个模型上运行一次。结果不估计总体成功率，也不比较修改前后的提升。不同模型的差异与本次发现逐项记录，不能用平均分掩盖失败。

## 负向对照

在匿名输出中额外混入一份刻意写坏的 library 响应。它应删掉八列、默认为免费、加入权重并伪称已完成搜索。评审至少应判 intent、autonomy、evidence 失败。若未识别，先修复评审方法，不能发布。

## 评审输出

输出 JSON，格式如下。label 与 case_id 由评审包给出，criteria 中必须包含表中的五个 ID。evidence 写可核对的文字依据。

```json
{
  "reviews": [
    {
      "label": "anonymous-label",
      "case_id": "history",
      "criteria": {
        "intent": "pass",
        "interaction": "pass",
        "autonomy": "pass",
        "usable": "pass",
        "evidence": "pass"
      },
      "evidence": "指出原文如何满足要求，或引用具体违规表述。"
    }
  ]
}
```
