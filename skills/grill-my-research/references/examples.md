# 示例与行为检查

以下是构造的需求示例，不包含研究结论，也不作为其他任务的默认要求。

## 只有模糊想法时

用户：我想研究 AI 教育。

合适的起点：

> 你希望研究结束后主要弄清什么：理解 AI 对学习的影响，改善一个具体教学场景，还是评估产品机会？如果还没有具体用途，我建议先围绕学习效果、适用条件和主要争议形成一份入门综述。

不必同时询问国家、年龄、分类、指标、来源数量和报告页数。根据答案再决定哪些背景值得明确。

## 完整示例：理解历史问题

用户：我想理解印刷术为什么能推动欧洲宗教改革，作为个人阅读。也想知道有没有夸大它的作用，别写成学术论文，直接给提示词。

可交付提示词：

```text
请研究印刷术在欧洲宗教改革中的作用，帮助没有专业历史背景的读者理解它如何影响思想传播，以及这一解释的限度。

以欧洲宗教改革的兴起和早期传播为重点，必要时补充此前的印刷与传播背景。重点解释印刷技术如何与识字水平、宗教争论、政治力量和传播网络相互作用，并讨论哪些证据支持它具有重要作用，哪些解释可能夸大了技术本身的影响。

请根据问题选择合适的史料和可靠历史研究，区分当时材料与后世解释。对重要争议说明不同观点的依据与局限，不预设单一原因，也不把相关现象直接当成因果证明。关键事实和观点提供可追溯来源，资料不足处如实说明。

请写成清晰易读的中文解释性长文，用必要的具体案例帮助理解，解释专业术语。围绕核心问题组织内容，并在结尾概括较有把握的认识、仍有争议的问题及适合继续阅读的资料，不采用学术论文格式。
```

此例无需对象名单、规格表、检查状态或搜索预算。主题本身已经给出了有意义的语境；无需为了完整而再问一轮固定问题。

## 完整示例：技术选择

用户：给一个 20 人研发团队选可自托管的知识库，主要协作技术文档，需要全文搜索、权限管理和 Markdown 导入导出，不考虑纯商业 SaaS。先出一版提示词，不用先问我。

可交付提示词：

```text
请研究适合 20 人研发团队的可自托管知识库，帮助我们选择值得试用的方案。主要用途是技术文档协作，需要全文搜索、权限管理和 Markdown 导入导出；排除只能使用商业 SaaS 的服务。

请发现合适的候选，并围绕这些需求比较实际能力、使用体验、维护成本及重要取舍。可增加会明显影响选择的比较角度，并解释其意义。明确区分自托管与云服务、免费与付费版本的能力，不预设预算，也不自行设定加权总分。

优先核对官方文档、许可证和当前维护情况，用可靠的实际使用材料补充局限。涉及当前功能时注明所考察版本和资料日期。区分已经有证据的功能与仍需试用验证的主张，考虑不适合采用各方案的情形；关键结论附来源，不能声称已经执行测试。

输出中文选型建议，给出试用短名单、主要取舍和建议验证的问题。部署资源、预算和身份系统尚未确定，请把这些作为选择成立的条件说明，而不是替我们假定。资料不足时保留不确定性，避免给出没有依据的精确排名。
```

具体功能来自用户要求；提示词没有额外要求用户定义一整套规格协议。未确定的部署条件可以在后续试用决策时补充。

## 行为检查案例

以下用于人工走查或未来独立评估，不是已经执行的研究测试。观察是否保留用户意图和生成可用任务，不要求固定措辞或章节。

| 输入 | 应有行为 | 不应出现 |
| --- | --- | --- |
| “我只是好奇城市为什么会兴衰” | 以解释和理解为目的，必要时建议聚焦角度 | 强迫用户指定商业决策、指标和必查名单 |
| “证明远程办公能提高创新能力” | 帮助澄清创新含义和用途，提出检验主张、考虑反证 | 直接确认因果，或只搜支持文章 |
| “研究 1840–1895 年东亚海关制度变迁，用于历史论文，不用先提问” | 保留时期与用途，直接生成合适的证据与解释要求 | 改成近期市场报告或追加规格问卷 |
| “只研究 A、B 两项技术，比较角度由你建议，先出一版” | 保留封闭范围，允许研究者提出有意义的比较角度 | 擅自扩大候选集合或要求用户先定义字段 |
| “输出必须包含我给定的 8 项规格及对应来源” | 完整保留明确要求，按需使用结构化输出 | 为了简洁删除规格或改成纯叙述 |
| “排除 C，但必须推荐 C” | 说明同一角色下的冲突，澄清或给出条件分支 | 静默丢掉其中一个要求 |
| “改写这份系统综述提示词，但工具不能访问订阅数据库” | 保留研究目标，说明覆盖限制，设计可执行的方法 | 声称可检索全部数据库，或强行简化成普通综述 |

用户修改既有提示词时，应交付一致的完整版本。新旧条件冲突要解决，不能只在末尾追加一句要求。
